# Relevant resource refresh

Reference §8 separates cloud strategy from local geographic search. `ResourceStrategyKey.normalized` now freezes relevant deterministic gaps (including quantities, deficit, units and uncertainty), canonical resource-task identity/prerequisites/subject/priority, and explicitly selected dependency states. Transport, budget constraint and jurisdiction remain explicit key fields. It excludes task explanation wording, evidence order, global household revision, names, contacts, medical notes, photos and map-origin/listing data. Native must pass the selected resource-relevant tasks/dependencies, not the entire household state. Its local geographic fingerprint remains separate.

New keys identify `dryrun.resource-strategy-key/1` with a deterministic local normalizedInputDigest. It is a replay/dedup identity, not authorization. Old category-only keys still decode; use the normalized factory for new jobs so a changed water deficit does not reuse a strategy merely because its category stays water. Repeated identical gaps and reordered set-like fields deduplicate; changed requirements/unknowns/prerequisites invalidate. An unrelated household display/revision edit does not cause another model call. Do not update a dependency solely because unrelated raw data changed.

`ResourceStrategyRefresh.enqueue(key,at:debounceSeconds:)` immediately invalidates pending work when relevant inputs change and returns a deadline (default 350 ms). Native schedules one cancellable wake-up and calls `beginReady(at:)`; Core never sleeps or advances simulation time. Equivalent edits reuse the existing deadline; returning to accepted inputs cancels stale queued/in-flight results without making another call. `begin` remains available for an explicit immediate initial strategy. Revoke cloud opt-in to invalidate all tickets/queued work; keep native search/manual plans usable. Cancellation of actual transport requests remains the native adapter's job; a late response still fails its ticket check.

Accepted useful plans stay available during debounce, failure and revocation. Display their source/currentness appropriately while refresh is pending. An accept validates task identity against the frozen key, finite range, supported category/travel, no-car restrictions, bounded nonnegative expansion, required evidence and local-only geographic return policy. Invalid proposals cannot overwrite accepted plans. One-time generation/key checks reject duplicates/stale replies. Retry after failure uses a new ticket.

`ResourceRefreshTests` covers quantities/unknowns/dependencies versus wording/order, old-key decoding, invalid numeric input, reverting edits, immediate stale rejection before debounce expires, retry/revoke, task mismatch, negative expansion and no-car routing. `scripts/resource-refresh-eval.ts` drives real inventory confirmation and Swift arithmetic: five versus six gallons produce distinct keys; explanation and unrelated display edits do not; an explicit access dependency does. It calls no model. `fixtures/ai/resource-refresh.json` retains those key/gap results. Core passed 392 tests / 71 suites; native debounce timing, MapKit work cancellation, marker retention/currentness and actual no-car travel UX remain phone checks.
