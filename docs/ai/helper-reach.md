# Committed helper reach

Reference §§10–11 require committed helper actions to affect computed consequences. Policy-bound sessions now expose optional `SessionReceipt.assistance` after a submitted assignHelper command. The host recomputes helper-to-person routes from current exercise assignments/positions, geometry, mobility and committed hazard exclusions. It returns personID/helperID, reachStatus (reachable/unreachable/unknown/missingHelper), the local route, sharedWithPersonIDs and simultaneousCapacity. Unknown geometry stays unknown. Shared responsibilities are an explicit dependency; the host does not invent carrying limits, clinical capabilities or proof that sequential assistance is impossible.

A blocked helper route adds the current assistance reach requirement. A later actual reassignment or move can resolve it while retaining the earlier failed event in history. Source household/helper records remain unchanged. Dependency inspection now reads these current assignments instead of reporting the original household relationship after a reassignment. Candidate previews expose only minimized assistance IDs/statuses; local route geometry stays under the existing route minimizer.

This additive field is absent in older sessions and unchanged sessions without helper commands, preserving all retained legacy digests. It is included in the digest when present. It adds no score rule or practice credit. The scenario remains an educational graph assumption, not a real rescue instruction.
